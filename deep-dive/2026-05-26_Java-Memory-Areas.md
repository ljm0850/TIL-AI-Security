## 왜 찾아봤는가

`String s1 = "abc"`와 `String s3 = new String("abc")`가 왜 `==` 비교에서 다른 결과가 나오는지, `static` 변수는 왜 모든 인스턴스가 공유하는지가 강의만으로는 직관적으로 이해되지 않아서 메모리 구조 전체를 한번에 정리했다.

---

## 핵심 내용

### 4개 영역 요약

| 영역 | 저장 대상 | 공유 범위 | 수명 |
|---|---|---|---|
| Stack | 기본값, 참조값(주소), 리턴 주소 | 스레드별 독립 | 메서드 실행 동안 |
| Heap | 객체 인스턴스, 배열 | 모든 스레드 | GC가 수거할 때까지 |
| Method Area | 클래스 메타데이터, `static` 변수 | 모든 스레드 | JVM 종료 시까지 |
| Constant Pool | String 리터럴, 숫자·심볼 상수 | 모든 스레드 | JVM 종료 시까지 |

---

### Stack — "지금 실행 중인 것"

- 메서드 호출 시 **스택 프레임** 하나가 쌓이고, 종료 시 자동 제거 (LIFO)
- 스레드마다 독립 → 다른 스레드가 접근 불가
- 기본 타입의 **값 자체**와, 객체를 가리키는 **참조값(주소)** 저장

```java
void main() {
    int x = 10;              // x = 10 (값 자체가 Stack에)
    Person p = new Person(); // p = Heap 주소 (주소가 Stack에, 객체는 Heap에)
}
```

---

### Heap — "만들어진 객체들"

- `new` 키워드로 생성한 객체·배열이 저장
- 모든 스레드 공유
- Stack의 참조값이 이 영역을 가리킴
- 더 이상 참조되지 않는 객체는 **GC(Garbage Collector)** 가 자동 수거

```java
Person p = new Person("이재민");
// "이재민" 데이터를 가진 Person 객체 → Heap
// p 변수(주소) → Stack
```

---

### Method Area — "클래스 설계도"

- 클래스 로딩 시 JVM이 클래스 정보를 올리는 곳
- **`static` 변수는 이곳에 저장** → 모든 인스턴스가 공유
- JVM 종료 시까지 유지

```java
class Counter {
    static int count = 0; // → Method Area (모든 인스턴스 공유)
    int id;               // → 인스턴스마다 Heap에 따로
}
```

> ⚠️ `static` 변수는 여러 스레드가 함께 접근하므로 동시성 문제 주의

---

### Constant Pool — "재사용 상수 창고"

- Method Area 안에 위치
- 컴파일 타임에 결정된 리터럴 상수 보관. **동일한 값은 하나만 존재**

```java
String a = "hello";  // Constant Pool의 "hello" 참조
String b = "hello";  // 동일 객체 참조 → a == b 는 true

String c = new String("hello"); // Heap에 새 객체 → a == c 는 false
```

**이것이 `==` 대신 `.equals()`를 써야 하는 이유다.**

- `==` → Stack에 저장된 주소(참조값) 비교
- `.equals()` → 주소가 가리키는 곳의 값 비교
