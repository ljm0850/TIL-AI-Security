# 닐슨 휴리스틱을 실제 서비스 평가에 적용하기
## — 취업준비생용 RAG 서비스 실전 가이드 (채용담당자 시나리오)

> **작성 맥락**: 인공지능사관학교 AI 보안 트랙 1주차 학습 내용(닐슨 10가지 사용성 휴리스틱)을 실제 토이프로젝트에 적용하기 위해 deep-dive한 내용을 정리한 문서.
> **대상 서비스**: GitHub 데이터 기반 개인 RAG 서비스 (자소서 작성 보조 + 채용담당자 접근 기능)
> **이 문서의 범위**: 채용담당자 시나리오
> **전제**: 취업준비생 시나리오(1차 MVP) 완성 후 2차로 구현할 시나리오

---

## 취업준비생 시나리오와의 핵심 차이

| 구분 | 취업준비생 | 채용담당자 |
|---|---|---|
| 서비스 숙련도 | 직접 만든 서비스 | 처음 보는 서비스 |
| 사용 빈도 | 자주 사용 | 한두 번 사용 후 끝 |
| 사용 목적 | 자소서 작성 보조 | 지원자 파악 |
| 접근 방식 | 직접 접근 | 토큰 기반 접근 |
| 대기 인내심 | 상대적으로 높음 | 상대적으로 낮음 |

---

## 핵심 사용 흐름

```
취업준비생이 회사/직무 정보 입력 + 토큰 발행
        ↓
채용담당자에게 토큰 전달
        ↓
채용담당자가 토큰으로 RAG 접근
        ↓
RAG 답변 확인
        ↓
(서류) 확인 후 종료 / (면접 전) 꼬리 질문 이어가기
```

---

## 사용 맥락: 서류 vs 면접

채용담당자는 채용 단계에 따라 사용 목적이 다르다.

| 단계 | 목적 | 사용 깊이 |
|---|---|---|
| 서류 | "이런 것도 준비했구나" 수준으로 확인 | 얕음 (빠르게 훑기) |
| 면접 전 | 질문 준비를 위해 탐색 | 깊음 (꼬리 질문 이어가기) |

이 차이가 각 단계의 설계 포인트에 영향을 준다.

---

## 단계별 휴리스틱 적용

### 단계 1: 취업준비생이 회사/직무 정보 입력 + 토큰 발행

채용담당자가 접근하기 전 취업준비생이 준비하는 단계.

**회사 정보 입력 시점에 대한 현실적 고려**

취업준비생 입장에서 서류 단계에 회사 정보를 정제하는 것은 심리적으로 어렵다. 면접이 확정되면 개인 면접 준비를 위해서라도 자연스럽게 정보를 정제하게 된다.

```
서류 단계: 대략적인 회사 정보 입력 (완성도 낮아도 무방)
        ↓
면접 확정 후: 취업준비생이 스스로 정보 정제
```

따라서 토큰 발행 후 회사 정보 수정을 제한할 필요 없이, 수정은 취업준비생의 책임 영역으로 둔다.

| 휴리스틱 | 설계 포인트 | MVP 여부 |
|---|---|---|
| 오류 방지 | 토큰 발행 전 입력 정보 미리보기 제공 | MVP |
| 사용자 제어 및 자유 | 토큰 발행 후에도 회사 정보 수정 가능 (제한 없이) | MVP |
| 시스템 상태의 가시성 | 현재 토큰 상태 표시 (발행됨 / 미발행) | MVP |

---

### 단계 2: 채용담당자가 토큰으로 RAG 접근

채용담당자는 링크와 토큰만 받고 처음 접근하는 사람이다. 서비스 구조를 모르는 상태에서 진입하므로 첫 경험 설계가 중요하다.

| 휴리스틱 | 설계 포인트 | MVP 여부 |
|---|---|---|
| 시스템과 실제 세계의 일치 | "토큰 입력" → "접근 코드를 입력하세요" 등 친숙한 언어 사용 | MVP |
| 기억보다 인지 | 접속 후 "○○○ 지원자에 대해 질문하세요" 명시 | MVP |
| 오류 방지 | 잘못된 토큰 입력 시 명확한 오류 메시지 | MVP |
| 도움말 및 문서화 | 질문 예시 제공 | MVP |
| 유연성과 효율성 | 질문 입력창 옆에 추천 질문 상시 노출 | 고도화 |

**추천 질문 기능 설계 방향**

서류 단계(빠르게 훑기)와 면접 단계(깊게 탐색) 모두를 자연스럽게 커버하기 위해 B 타입으로 설계한다.

```
A 타입 (진입 시 바로 제안): 서류 단계에 유리하나 면접 단계에서 방해될 수 있음
B 타입 (입력창 옆 상시 노출): 서류/면접 모두 자연스럽게 사용 가능 ← 채택
```

취업준비생 시나리오의 **유연성과 효율성** 휴리스틱과 동일한 원리 —
- 서류 단계(초보자) → 추천 질문에 의존
- 면접 단계(숙련자) → 직접 질문 입력

---

### 단계 3: RAG 답변 생성 중 (대기)

**취업준비생 시나리오와의 차이점**

채용담당자는 한두 번 쓰고 끝날 수 있는 사람이기 때문에 대기 인내심이 낮다. 취업준비생 시나리오에서 MVP를 단순 스피너로 잡은 것과 달리, 채용담당자 시나리오에서는 텍스트 피드백을 MVP로 올려야 한다.

| 휴리스틱 | 설계 포인트 | MVP 여부 |
|---|---|---|
| 시스템 상태의 가시성 | 텍스트 피드백으로 진행 단계 표시 ("데이터 검색 중..." → "답변 생성 중...") | MVP |
| 사용자 제어 및 자유 | 생성 중 취소 버튼 | MVP |

---

### 단계 4: 답변 확인

**취업준비생 시나리오와의 차이점**

| 구분 | 취업준비생 | 채용담당자 |
|---|---|---|
| 출처 표시 | 중요 | 더 중요 (신뢰도 확인 필요) |
| 재생성/수정 버튼 | MVP | 우선순위 낮음 (버튼 많으면 혼란) |

채용담당자는 "이 답변이 실제 지원자 데이터 기반인가?"를 확인해야 하므로 출처 표시가 특히 중요하다.

| 휴리스틱 | 설계 포인트 | MVP 여부 |
|---|---|---|
| 기억보다 인지 | 어떤 데이터를 참고했는지 출처 표시 | MVP |
| 오류 인식 및 복구 지원 | 관련 데이터 부족 시 명확히 안내 | MVP |
| 미니멀리즘 | 버튼 최소화, 핵심 정보만 노출 | MVP |

---

### 단계 5: 답변 이후

**취업준비생 시나리오와의 차이점**

취업준비생은 답변을 복사해서 자소서 작성으로 이어지지만, 채용담당자는 사용 목적이 다르다.

```
서류 단계: 확인 후 그냥 닫음
면접 단계: 추가 질문 이어서 입력 (꼬리 질문)
```

| 휴리스틱 | 설계 포인트 | MVP 여부 |
|---|---|---|
| 유연성과 효율성 | 복사 버튼 불필요 (취업준비생과 다른 점) | - |
| 사용자 제어 및 자유 | 꼬리 질문을 자연스럽게 이어갈 수 있는 대화 구조 | MVP |

## MVP 설계 요약

### 취업준비생이 준비하는 영역
- [ ] 토큰 발행 전 입력 정보 미리보기
- [ ] 토큰 발행 후 회사 정보 수정 가능
- [ ] 토큰 상태 표시 (발행됨 / 미발행)

### 채용담당자가 사용하는 영역
- [ ] 친숙한 언어로 된 토큰 입력 UI
- [ ] 접속 후 지원자 정보 명시
- [ ] 잘못된 토큰 입력 시 명확한 오류 메시지
- [ ] 질문 예시 제공
- [ ] 텍스트 피드백 로딩 (단계별 진행 상태)
- [ ] 생성 중 취소 버튼
- [ ] 참고한 데이터 출처 표시
- [ ] 데이터 부족 시 명확한 안내
- [ ] 꼬리 질문을 이어갈 수 있는 대화 구조
