## 핵심 인사이트 모음

### 📅 2026-05-26

- **추상화의 결과물이 결국 DB 구조다.** 명사를 추상화하면 정규화가 되고, 동사를 추상화하면 객체지향이 된다. 추상화 철학의 두 방향이다.
- **정규화는 쪼개는 것이고, JOIN은 다시 합치는 것이다.** 물리·화학·공학이 모든 것을 쪼개고 조합으로 해결하듯, 정규화도 데이터를 최소 단위로 쪼개고 필요할 때 JOIN으로 재조합한다. 차수가 높아질수록 중복은 줄고 JOIN은 늘어나는 이유가 여기에 있다.
- **정규화의 핵심은 중복 최소화와 이상 현상 방지다.** 삽입·갱신·삭제 이상은 모두 "같은 정보가 여러 곳에 있어서" 발생한다. 정규화는 그 근원을 제거한다.
- **실무는 보통 3NF 또는 BCNF에서 멈춘다.** 4NF, 5NF는 이론적으로는 완벽하지만, 그만큼 JOIN이 늘어나 조회 성능이 떨어진다. 성능이 중요한 곳에서는 역정규화(Denormalization)로 의도적으로 중복을 허용한다.
- **역정규화는 타협이지 설계 실패가 아니다.** 조회 위주의 데이터, 조인이 많아 성능이 저하되는 경우에 제한적으로 적용하되, 충돌이 발생하면 무결성이 우선이다.

## 1. 데이터베이스 설계 4단계

### 핵심 개념

설계는 집을 짓기 전 설계도를 그리는 과정이다. 단순히 표를 만드는 게 아니라, 데이터를 어떻게 구조화해야 중복 없이 안전하고 빠르게 꺼내 쓸 수 있을지 결정하는 작업이다.

### 상세 내용

| 단계 | 이름 | 핵심 작업 |
|---|---|---|
| 1 | 요구사항 분석 (Analysis) | 무엇을 저장하고 어떻게 쓸지 정의. Use Case 기반 |
| 2 | 개념적 설계 (Conceptual) | ERD로 표현. 엔티티·속성·관계 정의. DB 엔진 독립적 |
| 3 | 논리적 설계 (Logical) | 관계형 테이블 구조로 변환. 정규화·PK·FK 정의 |
| 4 | 물리적 설계 (Physical) | 특정 DBMS에 맞게 타입·인덱스·파티셔닝 결정 |

**주요 용어**

| 용어 | 설명 | DB 용어 |
|---|---|---|
| 엔티티(Entity) | 업무에서 관리해야 할 객체 (예: 고객, 상품) | Table |
| 속성(Attribute) | 엔티티의 특성 (예: 고객명, 연락처) | Column / Field |
| 도메인(Domain) | 속성이 가질 수 있는 값의 범위 (예: 나이 = 0 이상의 정수) | |
| 인스턴스(Instance) | 엔티티의 실제 데이터 하나 | Row / Record / Tuple |

**좋은 설계 원칙**

- 데이터 중복 방지 (Minimizing Data Redundancy) — "복사 붙여넣기"를 "참조(Link)"로
- 무결성 유지 — 개체·참조·도메인 무결성
- 명확한 명명 규칙 — 예약어 금지, 일관된 표기법(카멜/스네이크)
- 확장성·유연성 — UI나 특정 구현에 종속되지 않도록
- 성능 고려 — 인덱스는 WHERE·JOIN·ORDER BY 기준 컬럼에 설계, 과도한 인덱스는 쓰기 성능 저하

## 2. ERD

### 핵심 개념

ERD(Entity-Relationship Diagram): 데이터 구조와 엔티티 간 관계를 시각적으로 표현하는 모델링 도구다. 개발자·설계자·사용자 간 의사소통 도구이자 문서화 수단이다.

### 상세 내용

**주요 관계 종류**

| 관계 | 설명 | 구현 방식 |
|---|---|---|
| 1:1 | PK가 상대 테이블의 FK이자 PK로 연결 | |
| 1:N | 한쪽 PK가 다른 테이블에서 여러 번 나타남 | FK로 연결 |
| N:M | 직접 연결 시 중복 발생 | 조인 테이블(매개 테이블)로 1:N 두 개로 분리 |

## 3. 정규화 (Normalization)

### 핵심 개념

- 데이터 중복을 제거하고, 삽입·갱신·삭제 이상 현상을 방지하기 위해 테이블을 분리하는 과정
- 차수가 높아질수록 중복 감소 ↔ JOIN 증가 (트레이드오프)
- 실무에서는 일반적으로 **3NF 또는 BCNF** 수준에서 종료

### 상세 내용

**이상 현상 3종류**

| 종류 | 설명 |
|---|---|
| 삽입 이상 | 데이터 추가 시 불필요한 부가 정보까지 함께 추가해야 함 |
| 갱신 이상 | 일부만 수정되어 같은 내용의 다른 데이터와 불일치 발생 |
| 삭제 이상 | 하나의 정보를 삭제할 때 유지되어야 할 다른 정보까지 함께 삭제됨 |

**함수적 종속성 (Functional Dependency)**

- `X → Y`: X가 Y를 결정한다. X = 결정자(Determinant), Y = 종속자(Dependent)
- 완전 함수 종속: 복합키 전체에 종속 (예: {학번, 과목} → 성적)
- 부분 함수 종속: 복합키의 일부에만 종속 (예: {학번, 과목} → 이름 ← 학번만으로 결정됨)
- 이행 함수 종속: `X→Y, Y→Z`이면 `X→Z` (예: 학번→학과코드, 학과코드→학과명 ⇒ 학번→학과명)

**정규형 단계 요약**

| 단계 | 조건 | 제거 대상 |
|---|---|---|
| 1NF | 모든 속성 값이 원자값(Atomic Value) | 다중값, 반복 속성 |
| 2NF | 1NF + 완전 함수 종속 | 부분 함수 종속 |
| 3NF | 2NF + 비키 속성 간 종속 제거 | 이행 함수 종속 |
| BCNF | 3NF + 모든 결정자가 후보키 | 후보키가 아닌 결정자 |
| 4NF | BCNF + 다치 종속 제거 | Multi-valued Dependency |
| 5NF | 4NF + 조인 종속 제거 | Join Dependency |

## 4. 역정규화 (Denormalization)

### 핵심 개념

성능을 위해 의도적으로 중복을 허용하는 과정. 정규화와 성능 사이의 균형점이다.

### 상세 내용

- 무결성과 성능이 충돌하면 **무결성이 우선**
- 제한적으로 사용 — 남용 시 이상 현상 재발
- 적용 시점: 수정이 없고 조회 위주인 데이터, 조인이 많아 성능 저하 발생 시, 자주 조회되는 연산을 미리 계산해서 저장할 때
