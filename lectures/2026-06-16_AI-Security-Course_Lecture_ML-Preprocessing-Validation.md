## 핵심 인사이트 모음

### 📅 2026-06-16

- **머신러닝이 왜 필요한가**가 오늘 한 문장으로 정리됐다. 과거엔 인간이 방정식으로 변수 간 관계를 정의했는데, **이제 방정식으로 풀기엔 불가능에 가까운 문제만 남았다.** 그래서 인간이 식을 세우는 대신, 데이터로 알고리즘이 관계를 찾게 하는 게 ML이다. 그러니 우리가 할 일은 "이 데이터가 정말 그 관계(방정식의 해)를 찾는 데 도움이 되는가"를 먼저 판별하는 것 — 그게 데이터 분석/전처리다.
- 선형대수의 핵심은 행렬이고, **행렬 연산을 가장 잘 굴리는 하드웨어가 GPU**라는 점이 흥미로웠다. 원래 게임 그래픽 때문에 행렬을 대량으로 처리하려고 만든 GPU가, 같은 이유로 ML/딥러닝 연산을 가속하게 된 흐름이 연결됐다.
- "통계는 결국 **집단을 대표하는 대표값(가장 많이 선택될 만한 값)**을 찾는 것"이라는 정의가, 전처리에서 결측치를 평균/중앙값/최빈값으로 채우는 작업과 그대로 이어졌다. 결측치를 채운다는 건 그 자리에 "가장 그럴듯한 대표값"을 넣는 일이다.
- **어제 궁금했던 게 오늘 풀렸다.** 어제 "`random_state`만 바꿔도 정확도가 출렁이는데 이 숫자 하나를 믿어도 되나, 교차검증이 이걸 푸는 건가"라고 적어뒀는데, 오늘 k-fold / StratifiedKFold가 정확히 그 답이었다. **한 번 잘라 한 번 재는 게 아니라, 여러 번 잘라 여러 번 재서 평균**을 보는 것. 한 번의 운(분할 seed)에 휘둘리지 않게 만드는 장치였다.
- **정밀도(Precision) vs 재현율(Recall)은 상황에 따라 무엇을 우선할지가 갈린다.** 강의 예시가 직관적이었다 — 의사가 입원 여부를 결정하는 코로나 키트는 "양성이라 했으면 진짜 양성이어야"(정밀도 우선), 일반인용 키트는 "증세 있으면 일단 다 잡아내야"(재현율 우선). **이건 AI 보안의 침입탐지와 똑같은 트레이드오프다** — 오탐(FP)을 줄일 거냐, 미탐(FN)을 줄일 거냐. 보안은 보통 미탐이 더 치명적이라 재현율 쪽에 무게가 실린다는 게 자연스럽게 연결됐다.

## 1. 데이터 전처리(Data Preprocessing)

### 핵심 개념
- 결측치·이상치·과제와 무관한 값을 **과제에 적합한 데이터셋으로 가공**하는 것.
- 분류: 데이터 정제(Cleaning) / 데이터 변환(Transformation) / 데이터 통합(Integration) / 데이터 축소(Reduction).

### 상세 내용

**(1) 결측치(Missing value)**
- Pandas는 `None`, `NaN`, `NaT`를 결측치로 본다.
- 비율 확인: `df.isnull().sum() / len(df)`.
- 처리: 삭제 `dropna()` / 채우기 `fillna()` / 보간 `interpolate()`.
- sklearn: `SimpleImputer(strategy='mean'|'median'|'most_frequent'|'constant')`.
- 판단 기준: 결측이 너무 많은 열(예: 40%+)은 차라리 삭제, 수치형은 분포를 보고 평균/중앙값, 범주형은 최빈값.

**(2) 범주형 인코딩(Encoding)**
- 대부분 알고리즘이 문자보다 숫자를 선호 → 텍스트를 숫자로 바꾸는 게 인코딩.
- **레이블 인코딩**: 값을 정수로(`pd.factorize`, `LabelEncoder`). 한 열에 저장 → **선형회귀 등은 이 정수를 크기로 오해**할 수 있음(2 > 1처럼).
- **원-핫 인코딩**: 값마다 열을 만들어 해당만 1, 나머지 0(`pd.get_dummies`, `OneHotEncoder`). 위 크기 오해 문제를 해결하지만 열이 늘어난다.
- 기준(내 정리): **분류 개수가 적으면 레이블, 많으면 원-핫**이 강의에서 준 실무 감각.

**(3) 피처 스케일링(Feature Scaling)**
- 편차/비대칭(skewness)이 심하거나 단위가 다른 피처들의 범위를 맞추는 작업.
- **표준화(Standardization, `StandardScaler`)**: 평균 0, 표준편차 1로. (Z-score)
- **정규화(Normalization, `MinMaxScaler`)**: 0~1 범위로. (min-max)

**(4) 파이프라인(Pipeline)**
- 전처리~학습의 여러 단계를 **하나의 객체로 묶어** 순서대로 실행.
- 내부 단계는 `fit`/`transform`이 구현돼 있어야 함.
- 핵심 이점: 데이터셋이 파이프라인 내부에서만 흘러 **부수효과(side effect)를 막는다.** (= scaler를 train에만 fit하고 test엔 transform만 하는 규칙을 자동으로 지켜줘서, test 정보가 학습에 새어드는 누수를 방지)

## 2. 검증(Validation)

### 핵심 개념
- 모델의 **일반화 정도**를 확인하는 방법. 과대적합/과소적합의 영향을 줄이려고 데이터를 나눠 학습·검증한다.

### 상세 내용
- **홀드아웃(holdout)**: train / test로 한 번 나눔. 간단하지만 데이터가 적거나 분할이 편향되면 흔들린다.
- **k-fold**: 데이터를 k조각으로 나눠, 한 조각씩 돌아가며 검증용으로 쓰고 나머지로 학습 → k번 평가 후 평균. 데이터 수와 무관하게 쓰지만 시간이 든다.
- **StratifiedKFold**: 기계적으로 자르는 k-fold는 **레이블을 무시**해서, 정렬된 데이터의 경우 한 fold에 특정 레이블만 쏠릴 수 있다. Stratified는 **전체 레이블 분포(비율)를 각 fold에 유지**시켜 이 문제를 해결한다.

## 3. 성능 평가

### 핵심 개념
- 모델이 얼마나 정확히 예측하는지를 성능으로 표현. **알고리즘 종류에 맞는 지표 선택**이 중요.

### 상세 내용

**(1) GridSearchCV (GridSearch + Cross Validation)**
- 하이퍼파라미터 후보 조합을 **다 학습시켜 보고**, 내부적으로 K-fold 교차검증으로 평가해 **최적 조합을 자동으로 찾아준다.**
- 주요: `param_grid`(dict), `cv`(기본 5), `best_score_`, `best_params_`, `best_estimator_`.

**(2) 오차행렬(Confusion Matrix)** — 예측 기준

| 실제 \ 예측 | Positive | Negative |
|---|---|---|
| **Positive** | TP (맞게 맞힘) | FN (맞는데 틀리다 함) |
| **Negative** | FP (틀린데 맞다 함) | TN (틀리게 틀림) |

**(3) 분류 지표**
- **정확도(Accuracy)** = (TP+TN) / 전체. 분포가 균일할 때 신뢰. **편향(불균형) 데이터에선 왜곡**된다.
- **정밀도(Precision)** = TP / (TP+FP). **예측한 Positive 중** 진짜 Positive 비율. → "양성이라 했으면 진짜여야" (의사용 키트).
- **재현율(Recall, 민감도)** = TP / (TP+FN). **실제 Positive 중** 잡아낸 비율. → "있으면 다 잡아내야" (일반인용 키트).
