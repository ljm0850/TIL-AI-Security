- "EC2에 도커로 프론트엔드/백엔드/DB 컨테이너 다 띄우면 되는데 왜 굳이 RDS를 쓰나?"라는 의문이 있었는데, 핵심은 "돌아가게 만드는 것"과 "운영 가능하게 만드는 것" 사이의 간극이었음. 직접 띄운 DB 컨테이너는 백업/복구/패치/모니터링/고가용성을 전부 스스로 챙겨야 하는데, RDS는 그걸 관리형으로 대신 해준다는 것. 이건 지금까지 "일단 돌아가면 끝"이라는 감각으로 접근했던 부분을 다시 보게 만드는 지점이었음.

## 1. AWS 스토리지 서비스

### 핵심 개념
- 스토리지: 데이터를 보관하는 장소 (USB, SSD 등과 개념적으로 동일)
- 스토리지는 저장 방식에 따라 블록 / 파일 / 객체 스토리지로 구분됨

### 상세 내용
- **블록 스토리지**: 단일 스토리지 볼륨을 블록 단위로 분할하여 저장
  - SAN(Storage Area Network): 서로 다른 종류의 데이터 저장 장치를 한 데이터 서버에 연결해 관리하는 네트워크
- **파일 스토리지**: 디렉터리 구조로 파일을 저장
  - NAS(Network Attached Storage)
  - 다수의 장치가 데이터를 공유하며 동일한 서비스를 사용해야 하는 경우에 적합
- **객체 스토리지**: 데이터를 객체 단위로 저장
  - REST 기반 API 호출을 통해 접근
  - 다수의 서버에서 해당 데이터에 접근해야 하는 경우에 적합

## 2. Amazon EBS

### 핵심 개념
- EC2 인스턴스에서 사용할 수 있는 **블록 스토리지** 볼륨 제공 서비스

### 상세 내용
- 특징: 가용성, 지속성, 안정성, 백업, 확장성
- 스냅샷: 특정 시점을 기준으로 되돌아갈 수 있는 지점을 만드는 기능. 변경된 부분만 증분 백업됨 (GitHub 버전 관리와 비슷한 감각으로 이해)

## 3. Amazon EFS

### 핵심 개념
- 클라우드 환경과 온프레미스 환경 모두에서 사용할 수 있는 완전 관리형 **네트워크 파일 시스템** (파일 스토리지)

### 상세 내용
- 프로비저닝, 유지 관리, 소프트웨어 구성, 모니터링 등을 AWS가 전부 관리

---

## 4. Amazon S3

### 핵심 개념
- Simple Storage Service, **객체 스토리지** 서비스

### 상세 내용
- 높은 내구성으로 데이터 손실 최소화
- 웹 접속이 가능하여 정적 웹 콘텐츠를 S3에 올리면 웹 서버 없이 바로 웹 서비스 가능
- IAM으로 접속 사용자 및 데이터 접근 관리 가능

## 5. AWS 데이터베이스 서비스

### 핵심 개념
- 관계형 데이터베이스와 NoSQL로 구분

### 상세 내용
- **Amazon RDS**: 관계형 DB를 간편하게 설정·운영할 수 있는 관리형 서비스
  - PostgreSQL, MariaDB, Oracle Database, SQL Server 지원
  - Multi-AZ, Read Replica 방식으로 DB 복제
- **Amazon ElastiCache**: Redis 같은 NoSQL 인메모리 캐시 서비스

## 6. AWS IAM

### 핵심 개념
- 인증(Authentication): 사용자가 시스템에 들어갈 때 적법한 값을 가졌는지 확인
- 인가(Authorization): 인증 이후 사용자가 가진 권한을 확인

### 상세 내용
- 인증·인가 이후에는 **CloudTrail**을 통해 API 로깅이 가능
  - 계정의 거버넌스, 규정 준수, 운영 감사, 위험 감시를 지원

#### 구성 요소와 동작 방식
- **AWS 계정 루트 사용자**: 계정 최초 생성 시의 사용자, 해당 계정의 모든 권한 보유
- **IAM 사용자(User)**: 계정 내 사용자. 각자 자체 자격 증명을 보유하여 특정 AWS 작업 수행 권한을 통제 가능
- **IAM 그룹(Group)**: IAM 사용자의 집합. 그룹에 권한을 지정해 다수 사용자의 권한을 한 번에 관리
- **IAM 정책(Policy)**: 자격 증명이나 리소스에 연결되어 요청을 허용/거부하는 권한을 정의하는 객체
- **IAM 역할(Role)**: 특정 권한을 가진 계정에 생성할 수 있는 **임시** 자격 증명. 역할 세션을 위한 보안 자격 증명을 제공해 AWS 리소스 접근 권한을 위임
- **보안 주체(Principals)**: 루트 사용자, IAM 사용자, IAM 역할을 이용해 로그인하고 AWS에 요청하는 사람 및 애플리케이션
