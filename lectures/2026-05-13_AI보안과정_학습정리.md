## 1. UX vs UI

### 핵심 개념
- UX는 경험을 설계하고, UI는 그 경험을 화면으로 표현한다
- UX 먼저, UI 나중 — 순서가 뒤바뀌면 "보기엔 예쁘지만 쓰기 불편한 앱"이 탄생한다
- 올바른 작업 순서: 사용자 여정 분석 → 와이어프레임(UX) → 시각 요소(UI) → 개발

### 상세 내용

| 구분 | 정의 | 비유 |
|---|---|---|
| **UX (User Experience)** | 사용자가 제품을 이용하는 과정에서 느끼는 총체적 경험 | 건물의 설계도 — 동선·구조·편의성 |
| **UI (User Interface)** | 사용자가 마주하는 시각적·기능적 접점 (버튼, 색상, 아이콘 등) | 건물의 인테리어 — 벽지·가구·마감재 |

## 2. 닐슨 휴리스틱 10원칙

### 핵심 개념
- 제이콥 닐슨(Jakob Nielsen)이 제안한 사용성 평가의 30년 검증 기준
- 좋은 UI인지 판단하는 체크리스트로 활용

### 상세 내용

| 원칙 | 설명 | 예시 |
|---|---|---|
| **시스템 상태의 가시성** | 현재 진행 상황을 피드백으로 명확히 알려야 함 | 로딩 바, 진행률 표시 |
| **시스템과 실제 세계의 일치** | 전문 용어 대신 사용자에게 친숙한 언어 사용 | 'Error 404' → '페이지를 찾을 수 없습니다' |
| **사용자 제어 및 자유** | 실수 시 벗어날 수 있는 명확한 탈출구 제공 | Undo / Redo, 삭제 취소 버튼 |
| **일관성과 표준** | 동일한 기능은 항상 같은 방식(단어·아이콘·레이아웃)으로 제공 | 플랫폼 관례 준수 |
| **오류 방지** | 오류 메시지보다 오류 자체가 발생하지 않도록 미리 설계 | 이메일 형식 실시간 검증, 삭제 전 재확인 창 |
| **기억보다 인지** | 사용자가 정보를 기억하지 않아도 되도록 화면에 가시적으로 노출 | 필요한 옵션·액션을 화면에 항상 표시 |
| **유연성과 효율성** | 숙련자와 초보자 모두 배려 — 숙련자용 '가속기' 제공 | 단축키, 개인화 설정 |
| **미니멀리즘과 미적 디자인** | 불필요한 정보는 핵심 콘텐츠의 가치를 희석 | 간결하고 깔끔한 디자인 유지 |
| **오류 인식 및 복구 지원** | 오류 원인을 구체적으로 명시하고 실질적 해결 방안 제시 | 단순 경고가 아닌 해결 안내 |
| **도움말 및 문서화** | 설명서 없이 쓰는 것이 최선, 필요 시 즉시 찾을 수 있는 도움말 제공 | 구체적 단계로 구성된 간결한 도움말 |

## 3. 화면 설계의 3단계

### 핵심 개념
- IA → 화면흐름도 → 와이어프레임 → 프로토타입 순으로 진행
- 전체 구조를 먼저 잡고 세부 화면을 채우는 방향

### 상세 내용

**IA (Information Architecture) — 서비스의 뼈대**
- 전체 메뉴와 정보를 논리적으로 분류·계층화한 지도
- 3대 원칙: **직관성** (멘탈 모델과 메뉴 명칭 일치) / **효율성** (최소 클릭으로 원하는 정보 도달) / **일관성** (서비스 전반 동일한 내비게이션 규칙)

**화면흐름도 (Screen Flow) — 사용자의 여정**
- 사용자가 목적 달성을 위해 이동하는 경로 시각화
- 표기법: 사각형(화면) / 다이아몬드(분기점) / 화살표(이동 방향·액션)

**와이어프레임 vs 프로토타입**

| 구분 | 특징 | 목적 |
|---|---|---|
| **와이어프레임** | 흑백·무채색, 텍스트와 박스만 구성 | 논리적 구조·레이아웃에 대한 팀 합의 도출 |
| **프로토타입** | 인터랙션(클릭, 화면 전환) 결합, 동적 상태 | 실제 사용 환경 문제 발견, 사용자 테스트(UT) |

**피델리티(Fidelity) 3단계**

| 단계 | 특징 | 활용 시점 |
|---|---|---|
| **Lo-Fi** | 손스케치, 단순한 틀 | 아이디어 발산 및 초기 컨셉 확인 |
| **Mid-Fi** | 흑백 와이어프레임, 정돈된 배치 | 팀 내 기능 확정 및 구조적 피드백 수렴 |
| **Hi-Fi** | 실제 디자인, 인터랙티브 구현 | 최종 사용자 테스트 및 개발 전달(Hand-off) |

## 4. Figma 핵심 기능

### 핵심 개념
- 업계 표준 올인원 디자인 도구 — 와이어프레임부터 프로토타입까지 한 곳에서
- Component + Auto Layout 조합이 디자인 시스템의 기초

### 상세 내용

**핵심 기능 5가지**

| 기능 | 설명 |
|---|---|
| **Frame** | 하나의 화면(Screen)을 담는 컨테이너. iPhone·Desktop 등 디바이스 규격 선택 생성 |
| **Layer** | 화면 구성 요소들의 계층 구조. 상단 레이어일수록 앞에 표시. 그룹화(Group)로 관리 |
| **Component** | 버튼·카드·헤더 등 반복 요소를 부품화. 마스터 수정 시 모든 인스턴스에 자동 반영 |
| **Auto Layout** | 요소 추가·삭제 시 레이아웃 자동 조정. Shift+A로 활성화. Padding·Gap 수치 제어 |
| **Variables** | 색상·수치·텍스트 등에 이름(Token) 부여 관리. 다크모드 전환·다국어 대응 클릭 한 번 |

**프로토타입 연결 3단계**
1. 우측 사이드바에서 **Prototype** 탭 클릭
2. 상호작용 시작 요소 선택 → 파란색 핀(Node) 드래그 → 목적지 프레임에 연결
3. 트리거(On Click) + 액션(Navigate To) + 트랜지션 종류 설정

**Component + Auto Layout 시너지**
- 버튼 텍스트 길이가 달라져도 Padding 값에 따라 버튼 크기 자동 최적화
- 마스터 컴포넌트 하나만 수정하면 수백 개 인스턴스 동시 업데이트

## 5. 사용자 여정 지도 (User Journey Map)

### 핵심 개념
- 화면 설계 전에 경험 전체를 먼저 그린다 — 여정 지도가 와이어프레임의 나침반
- 감정 곡선이 급격히 하락하는 지점 = 가장 치명적인 Pain Point = Figma에서 가장 먼저 설계해야 할 화면

### 상세 내용

**작성 5단계 프로세스**
1. **페르소나 및 목표 설정** — 여정의 주인공과 최종 목표 정의
2. **단계(Stage) 정의** — 여정을 5~7개 주요 단계로 구분 (예: 인지 → 탐색 → 구매 → 사용)
3. **행동 및 터치포인트 기록** — 각 단계에서 사용자 행동과 제품 접점 상세 기입
4. **감정 곡선 작성** — 단계별 만족도를 시각적 곡선으로 표현
5. **Pain Point 및 기회 도출** — 불편함 분석 → 개선 아이디어(Opportunities) 도출

**7대 구성요소**: 페르소나 / 시나리오 / 단계 / 행동 / 생각 / 감정 곡선 / 기회

**협업 도구**: FigJam (Figma 내장, 디자인 파일 연동 강력) / Miro·Canva (화이트보드 협업, 무료 템플릿)

## 오늘의 핵심 인사이트

- **UX 없는 UI는 예쁜 쓰레기다**: 화면을 먼저 예쁘게 만들고 UX를 고민하는 순서는 치명적인 결함을 만든다. POV → PRD → 여정 지도 → 와이어프레임으로 이어지는 흐름이 이해됐다.
- **닐슨 10원칙은 사용자 입장에서 생각하는 체크리스트다**: "오류 방지"가 "오류 메시지"보다 중요 — 에러가 안 나게 설계하는 게 더 좋은 UX. 과거 프로젝트에서 당연하게 적용해왔지만 당연하다고 생각해서 강조하지 않았다. 오늘 이 원칙을 통해 그게 상위 개념이었다는 근거가 생겼고, 앞으로는 의식적으로 꺼낼 수 있게 됐다.
- **Component + Auto Layout이 핵심이다**: Figma를 단순 그림 그리는 툴로 쓰면 수정이 힘들다. 직접 컴포넌트화 + 오토 레이아웃을 사용해보며 수정의 편리함에 차이가 크다는 걸 느꼈다.
- **여정 지도에서 감정 곡선이 급락하는 지점이 설계 우선순위다**: 우리 팀 키오스크 프로젝트에 적용 — 먹구름 씨의 감정이 가장 낮은 지점(키오스크 앞에서 멈추는 순간)이 첫 번째로 설계해야 할 화면이다.
- **Lo-Fi → Mid-Fi → Hi-Fi 순서는 비용 효율의 문제다**: 완성도가 낮을 때 수정하는 게 압도적으로 싸다. 처음부터 Hi-Fi로 가려는 욕심이 오히려 전체 작업량을 늘린다.
