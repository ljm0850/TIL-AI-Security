## 핵심 인사이트 모음

### 📅 2026-07-22

- **위험 = 발생 가능성 × 영향도.** 그래서 팀에 보안을 설득하려면 기능이 아니라 '피해(영향도)'부터 보여줘야 한다.
- **"클라이언트를 믿지 말자"는 구현할 때 떠올릴 게 아니라 설계 단계에서 못 박아야 하는 원칙이다.** 이전 팀 프로젝트에서 프론트엔드 조작만으로 값을 변조·반영할 수 있는 취약점을 시간 부족으로 남긴 적이 있는데, 그건 설계 단계에서 이 원칙을 안 세워서 생긴 빚이었다.
- **무결성은 결국 '로그로 증명 가능한 상태'다.** STRIDE의 Repudiation(부인 방지)이 왜 로깅을 요구하는지가 여기서 이어진다.

## 1. 보안의 정의와 CIA Triad

### 핵심 개념
- 보안(Security) = 자산(데이터·SW·HW·인프라)을 위협으로부터 보호해 **기밀성·무결성·가용성**을 유지하는 활동.

### 상세 내용

| 요소 | 정의 | 유지 기술 |
|---|---|---|
| 기밀성 (Confidentiality) | 인가된 사용자만 접근 | 암호화, 접근 제어, MFA |
| 무결성 (Integrity) | 인가 없이 변경·삭제·위조되지 않음 | 디지털 서명, 해시(SHA-256), 변경 이력 |
| 가용성 (Availability) | 필요할 때 언제든 접근 가능 | DDoS 방어, 이중화, 백업 |

- 일반적인 개발자 입장에서 가장 신경 써야 할 자산은 결국 **DB**라는 생각. 기밀성 쪽으로는, 예전에 비밀번호 외의 민감 정보 암호화는 고민해 본 적이 없었는데 다시 볼 지점.

## 2. 보안 · 안전 · 프라이버시 / 위협 · 취약점 · 위험

### 핵심 개념
- **보안**은 고의적 공격(Adversary)으로부터, **안전(Safety)**은 비의도적 사고(오작동·재해)로부터, **프라이버시**는 정보 자기결정권을 다룬다.

### 상세 내용

| 개념 | 의미 | 예시 |
|---|---|---|
| 위협 (Threat) | 손해를 끼칠 수 있는 잠재적 사건·공격자 | 악성코드 유포, 해커 그룹 |
| 취약점 (Vulnerability) | 방어 체계를 우회하게 만드는 약점·결함 | 미패치 버그, 관리 부실 |
| 위험 (Risk) | 위협이 취약점을 이용할 때의 기대 손실 | — |

- **위험 산출 공식 (NIST SP 800-30)**: `위험(Risk) = 발생 가능성(Likelihood) × 영향도(Impact)`
  - 발생 가능성 = 취약점 노출 수준·위협 빈도. 영향도 = 자산 가치가 클수록 커짐.

## 3. 공격 경로와 위협 모델링

### 핵심 개념
- **STRIDE**: MS가 만든 위협 모델링 프레임워크. 위협을 6종으로 분류하고 각각 대응 보안 속성을 매핑한다.

### 상세 내용

| 위협 요소 | 설명 | 대응 보안 속성 |
|---|---|---|
| Spoofing (신분 위장) | 다른 사람·시스템 권한을 사칭 | 인증 (Authentication) |
| Tampering (데이터 변조) | 전송·저장 데이터를 인가 없이 수정 | 무결성 (Integrity) |
| Repudiation (부인 방지 실패) | 행위 사실을 입증 못 함 | 부인 방지 (Non-repudiation) |
| Information Disclosure (정보 유출) | 기밀 데이터를 비인가자가 열람 | 기밀성 (Confidentiality) |
| Denial of Service (서비스 거부) | 자원 고갈로 서비스 방해 | 가용성 (Availability) |
| Elevation of Privilege (권한 상승) | 낮은 권한이 관리자 권한 획득 | 권한 부여 (Authorization) |

- **공격 표면(Attack Surface)** = 공격자가 도달 가능한 모든 지점(노출 포트, 웹 양식, API). **공격 벡터(Attack Vector)** = 그 표면을 뚫는 구체적 경로·수단(피싱 이메일, SQL 인젝션).
- **공격자 유형**: 내부자 / 해커 / 국가 지원 APT / 자동화 봇.
- **사이버 킬체인 (록히드 마틴, 7단계)**: 정찰 → 무기화 → 전달 → 취약점 공격 → 설치 → 명령·제어(C2) → 목표 달성. 방어자는 한 단계라도 끊으면 공격을 무력화할 수 있다.
- Spoofing/인증 항목을 보면서, 웹 개발의 JWT·Access/Refresh Token이 이 '인증' 자리에 해당하는 얘기 아닌가 하는 생각.

## 4. 보안 기술 분류

| 분류 | 기술 | 역할 |
|---|---|---|
| 네트워크 | 방화벽 / IDS·IPS / VPN | 규칙 기반 트래픽 허용·차단 / 패킷 분석 탐지·차단 / 암호화 터널 |
| 엔드포인트 | Anti-Malware / EDR | 시그니처 기반 검사 / 실시간 행위 로그로 신종 위협 탐지·대응 |
| 애플리케이션 | OWASP Top 10 / WAF | 웹 취약점 방어 기준 프레임워크 / 웹 방화벽 |
| 아이덴티티 | IAM / Zero Trust | 최소 권한 부여 / "아무도 믿지 말고 항상 검증" |
| 보안 운영 | SIEM / SOAR / 위협 인텔리전스 | 로그 수집·상관분석 / 플레이북 기반 자동 대응 / 외부 공격 정보 수집 |

## 5. 보안의 필요성과 규제

### 핵심 개념
- 디지털 전환(클라우드·IoT·생성형 AI)으로 공격 표면이 기하급수적으로 확대됐다. 이제 모든 엔드포인트·API·외부 연동 구간이 공격 경로가 된다.

### 상세 내용
- **침해 피해**: 금전(복구·랜섬 비용), 사회(신뢰도·브랜드 하락, 집단 소송), 국가(기반 시설 마비).
- **법적 의무**: 국내 개인정보보호법·정보통신망법, EU GDPR(심각 위반 시 전 세계 매출 4% 또는 2,000만 유로 중 큰 금액). 보안은 선택이 아니라 규제 준수 대상.
- **투자 vs 침해 비용**: 사후 수습·벌금·중단 비용이 사전 보안 투자를 크게 상회 → 사전 예방이 경제적.

## 6. 최신 보안 경향 (2023–2025)

- **공급망 공격 급증**: 신뢰하는 외부 오픈소스·써드파티를 오염(SolarWinds, XZ Utils 백도어). 신뢰 관계를 악용해 탐지가 어렵다.
- **RaaS(Ransomware as a Service)**: 랜섬웨어를 툴·대시보드로 대여 → 기술 낮은 범죄자도 실행.
- **제로데이 → N-day 자동 침투**: 패치는 공개됐지만 아직 적용 안 된 취약점을 역공학해 자동으로 침투 코드 제작. 패치 적용 전 공백기를 노림.
- **Zero Trust 가속**(NIST SP 800-207), **AI 이용 공격**(딥페이크, LLM 대량 피싱).
