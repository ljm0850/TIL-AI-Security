## 1. RAG 개요

### 핵심 개념
- LLM은 과거에 학습한 데이터를 기반으로만 답변한다 → 최신 정보나 특정 도메인 지식은 모를 수 있음
- RAG(Retrieval-Augmented Generation): 리트리버가 데이터 조각(청크)을 미리 쌓아두고, 질문이 들어오면 유사한 조각을 찾아 언어모델에게 함께 건네서 그걸 근거로 답변하게 하는 구조

### 상세 내용
- RAG 시스템은 표준 구조가 없고 도메인마다 다르게 구성됨 → 도메인 자체에 대한 이해가 선행되어야 함

---

## 2. 청킹 (Chunking)

### 핵심 개념
- 대량의 문서를 작은 단위(쪽지 단위)로 자르는 작업

### 상세 내용
- 풀 컨텍스트를 그대로 전달했을 때 문제점
  - 언어모델이 한 번에 처리 가능한 텍스트 길이 제한
  - 문서 안에서 필요한 정보를 모델이 제대로 못 찾을 수 있음
  - 대화형으로 진행 시 매 턴마다 수백 페이지를 재입력 → 토큰 비용 급증

---

## 3. 임베딩 (Embedding)

### 핵심 개념
- 텍스트를 벡터(정보를 수치로 표현해 일렬로 나열한 것)로 변환하는 작업

### 상세 내용
- 벡터 간 **유사도** 계산에 주로 코사인 유사도 사용 — 두 벡터의 방향(각도) 기반으로 유사도 판단

---

## 4. 벡터 DB와 리트리버

### 핵심 개념
- **벡터 DB**: 임베딩된 벡터를 저장하고, 질문과 유사한 청크를 빠르게 찾아내도록 최적화된 저장소
- **리트리버**: 벡터 DB에서 유사도가 가장 높은 청크를 가져오는 역할

### 상세 내용
- 고차원 벡터에서 의미 유사성을 빠르게 계산·반환하도록 최적화됨
- 대표적인 벡터 DB: Chroma, FAISS, Pinecone
