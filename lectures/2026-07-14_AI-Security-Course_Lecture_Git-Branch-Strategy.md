## 1. Git 환경 설정 (복습)

### 핵심 개념
- `git config`의 적용 범위: `--global`(사용자 전체) / `--local`(현재 저장소만) / `--system`(시스템 전체)

### 상세 내용
- 사용자 정보 등록: `git config --global user.name`, `git config --global user.email`
- 이미 익숙한 부분이라 오늘은 복습 수준으로만 확인

---

## 2. Branch

### 핵심 개념
- 기능 개발이나 버그 수정을 기존 코드(main)와 분리해서 안전하게 작업하고, 완료 후 병합할 수 있도록 돕는 기능
- HEAD: 현재 작업 중인 브랜치의 마지막 커밋을 가리키는 포인터

---

## 3. Branch 전략

### 핵심 개념
| 전략 | 특징 |
|---|---|
| Git Flow | main / release / develop / feature / hotfix 로 구성 — 대규모 프로젝트에 적합 |
| GitHub Flow | main 브랜치 하나를 중심으로 운영, 복잡한 단계를 생략 — 수시 배포되는 웹/클라우드 서비스에 적합 |

### 상세 내용
- GitHub Flow 원칙: main은 항상 배포 가능한 상태를 유지, 새로운 작업은 무조건 새 브랜치에서 시작

---

## 4. 코드리뷰와 자동화 (기타)

### 핵심 개념
- 일반적인 개발 흐름: 코드 생성 → PR → 코드리뷰 → merge

### 상세 내용
- 최근 AI 도구로 코드 생산 속도가 빨라지면서, 사람이 그 속도만큼 코드리뷰를 진행하기 어려워지는 병목이 생기고 있음(평소에도 하던 고민)
- 해결 방향으로 코드리뷰·테스트의 어느 정도 자동화가 필요 → DevOps 영역의 문제
- Coderabbit 같은 AI 코드리뷰 자동화 도구가 언급됨(아직 직접 써보지는 않음)
