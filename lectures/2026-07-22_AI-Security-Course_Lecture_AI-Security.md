## 핵심 인사이트 모음

### 📅 2026-07-22

- **AI 취약점은 소스 코드가 아니라 모델(가중치)에 박힌다. 그래서 '패치'가 아니라 '재학습/교체'가 답이다.** 모델을 갈아 치워야 한다는 지점에서 MLflow(모델 버전·별칭·교체 관리)가 왜 필요한지가 이어졌다.
- **데이터 포이즈닝 방어는 결국 '누가·어디서 데이터를 검수하느냐'는 설계 문제다.** 간단한 RAG 파이프라인을 만들 때 문서를 사람이 검수하는 단계를 뒀던 게 바로 이 얘기였고, 서비스 성격에 따라 이 검수 지점을 어디에 둘지 고민이 커진다.
- **팀 프로젝트에선 모두 바이브 코딩을 쓸 테니, AI가 만든 코드·모델의 보안 검증이 흔한 리스크가 될 것이다.** 성능만 보다가 보안 결함을 놓치기 쉽다.

## 1. 전통 보안 vs AI 보안 & AI 생명주기

### 핵심 개념
- 전통 IT 보안: 입력→출력 관계가 **결정론적**. 규칙 기반 소스 코드를 보호하고, 취약점은 패치로 수정.
- AI 시스템: 입력에 대해 **확률적** 출력 → 위협 경계가 모호하고, 논리적 결함이 아니라 모델의 수학·알고리즘 특성을 악용하는 공격이 성립. 방화벽·침입 차단만으로는 AI 고유 위협을 막기 어렵다.

### 상세 내용

| 생명주기 단계 | 내용 | 주요 취약점 |
|---|---|---|
| 데이터 수집 | 학습용 원본 데이터 수집 | 무결성 훼손, 악의적 데이터 혼입 |
| 학습 (Training) | 데이터로 가중치 최적화 | 학습 파이프라인 제어권 탈취 |
| 배포 (Deployment) | 서비스·클라우드·엣지에 모델 탑재 | 모델 파일 탈취·변조 |
| 추론 (Inference) | 실사용 입력으로 예측·분류 | 실시간 입력 조작으로 오판 유도 |

## 2. AI 취약점의 특수성 & 확률적 한계

### 핵심 개념
- AI는 정형화된 코드가 아니라 **수억~수천억 개 가중치의 집합체**다.

### 상세 내용
- **데이터 포이즈닝(Data Poisoning)**: 학습 데이터를 미세하게 오염시키면 소스 코드는 멀쩡한데 가중치 내부에 은밀한 백도어가 심긴다 → 정적 코드 분석·전통 진단으로 탐지가 매우 어렵다.
- **패치로 못 고치는 확률적 취약점**: 특정 조건에서 비정상 출력·적대적 취약성이 나타나도 한 줄 패치로 못 막는다. 재학습해도 고차원 경계면이 변동하면서 다른 영역에서 새 취약점이 생길 수 있다.

## 3. AI 위협 분류 체계

### 핵심 개념
- 데이터 공급부터 최종 추론까지 **파이프라인 단계별 위협 지도**를 그려야 한다: 수집(포이즈닝) → 학습·저장(모델 도난·공급망) → 추론(회피·개인정보 추출).

### 상세 내용

**OWASP LLM Top 10 (2025)**

| 항목 | 위협 |
|---|---|
| LLM01 프롬프트 인젝션 | 악의적 프롬프트로 안전 가이드라인 우회, 공격자 명령 실행 유도 |
| LLM02 민감 정보 노출 | 학습 데이터에 있던 PII·기밀을 출력으로 유출 |
| LLM03 공급망 취약점 | 검증 안 된 외부 사전학습 모델·플러그인·데이터로 악성 코드 유입 |
| LLM04 데이터·모델 포이즈닝 | 학습·파인튜닝 데이터 조작으로 오판 유도·성능 저하 |
| LLM05 부적절한 출력 처리 | 검증 없는 출력을 하위 시스템에 전달 → SSRF·XSS 등 2차 취약점 |
| LLM06 과도한 자율성 | 인간 승인 없이 에이전트가 기능 실행 → 시스템 파괴·권한 남용 |
| LLM07 시스템 프롬프트 노출 | 핵심 운영 규칙(시스템 프롬프트)이 질의로 유출 |
| LLM08 벡터 DB 취약점 | RAG 벡터 DB에 오염 임베딩 주입·검색 쿼리 조작 |
| LLM09 허위 정보 | 환각(Hallucination)·악의적 가짜 뉴스 생성 |
| LLM10 무제한 소비 | 과다 요청으로 자원 고갈(DoS) + 과금 착취(Denial of Wallet) |

**STRIDE를 AI에 적용**

| STRIDE | AI 맥락의 예 |
|---|---|
| Spoofing | 신뢰 API 사용자로 가장해 모델 접근 |
| Tampering | 전송 중 학습 데이터·로컬 가중치 파일(.pth, .bin) 무단 수정 |
| Repudiation | 악성 요청 사용자의 감사 로그 누락 → 추적 불가 |
| Information Disclosure | 모델 역공학(Inversion)으로 학습 데이터 복원, 반복 쿼리로 모델 추출(Stealing) |
| Denial of Service | 처리 비용이 큰 입력으로 추론 서버 자원 점유 |
| Elevation of Privilege | 일반 권한으로 접근 후 프롬프트 인젝션으로 관리자 권한 Function Calling 실행 |

## 4. AI 보안 최신 현황 (2024–2025)

- **멀티모달 공격**: 사람 눈엔 정상인 이미지 픽셀에 악성 지시문을 숨겨 업로드 → 해석 과정에서 인젝션 명령이 가드레일을 무력화.
- **AI 에이전트 공격**: 에이전트가 읽을 외부 웹페이지에 **간접 프롬프트 인젝션**을 심어 둠 → 방문 순간 악성 지침 활성화(민감 메일 포워딩, 무단 시스템 명령). 브라우저 에이전트 관련 이슈가 떠올랐다.
- **RAG 시스템 포이즈닝**: 수집 대상 문서에 조작 텍스트 주입 → 벡터 DB 저장·검색되어 LLM 컨텍스트로 전달되면 시스템 전체 신뢰도가 무너짐.
- **모델 공급망 공격**: 오픈소스 사전학습 모델의 직렬화 파일(pickle 등)에 악성 코드 임베딩 → 로드 순간 RCE로 서버 제어권 탈취.
- **Red Teaming as a Service**: 확률적 취약점을 사전 탐지하는 AI 레드팀을 자동화 도구+전문가로 상시 제공하는 서비스형 비즈니스.
- **AI 거버넌스 내재화**: 개발 가이드라인·프라이버시 영향 평가·주기 감사를 조직·프로세스로 정립해 규제(EU AI Act 등)에 대응.

## 5. 규제

- **EU AI Act**: 세계 최초 포괄 AI 규제법. 위험도를 금지/고위험/제한/최소 4단계로 분류, 고위험군에 보안 검증·거버넌스 의무화.
- **NIST AI RMF**: AI 시스템의 신뢰성·안전성·보안성 확보를 위한 조직적 관리 지침.
- **KISA 가이드라인**: 국내 환경에 맞춘 AI 보안 개발·운영 기술적·관리적 요구사항.
