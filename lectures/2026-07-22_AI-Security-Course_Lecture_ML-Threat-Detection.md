## 핵심 인사이트 모음

### 📅 2026-07-22

- **보안 탐지에서 '정확도(accuracy)'는 함정이다.** 오탐(FP)과 미탐(FN) 중 무엇을 줄일지가 본질이고, 위협 탐지는 보통 미탐을 못 놓쳐서 **재현율**에 무게를 둔다.
- **TF-IDF는 '이 문서에만 쏠린 단어'를 뽑는 장치다.** 어디에나 나오는 흔한 단어(and, the)는 죽이고, 특정 문서에 집중된 단어를 살린다.
- **로지스틱 회귀는 계수를 보면 어떤 단어가 스팸으로 밀었는지 그대로 보인다.** 왜 그렇게 판단했는지 감사(audit)가 되는 게 이 조합의 보안적 강점이다.

### 📅 2026-07-23 (이어서)

- **엔트로피는 "내용이 무엇인지"는 못 알려주지만 "숨겼다는 사실"은 드러낸다.** 압축·암호화하면 데이터가 무작위에 가까워지므로, 파일을 실행하지 않고도 패킹 여부를 의심할 수 있다.
- **정적 분석은 실행하지 않아서 안전하지만, 그래서 패킹된 내부는 못 본다.** 안전과 관찰 범위가 맞바꿔지는 구조.

## 1. TF-IDF (Term Frequency–Inverse Document Frequency)

### 핵심 개념

- 텍스트를 수치 벡터로 바꾸는 통계적 가중치. 스팸 분류·악성 스크립트 탐지에서 텍스트를 특징화할 때 쓴다.

### 상세 내용

- **TF(단어 빈도)**: 특정 단어가 한 문서 안에서 나온 빈도. 많이 나올수록 그 문서에서 중요하다고 가정.
- **IDF(역문서 빈도)**: 전체 문서군에서의 희소성. 모든 문서에 흔한 단어는 가중치를 낮추고, 특정 문서에 집중된 단어는 높인다.
- 공식:
  - `TF(t,d) = (문서 d에서 단어 t 등장 횟수) / (문서 d의 전체 단어 수)`
  - `IDF(t,D) = log( |D| / (1 + |{d ∈ D : t ∈ d}|) )`
  - `TF-IDF(t,d,D) = TF × IDF`

## 2. 로지스틱 회귀 (Logistic Regression)

### 핵심 개념

- 선형 회귀 개념을 바탕으로 출력을 0~1 확률로 변환해 **이진 분류**를 수행. 메일이 스팸(1)인지 정상(0)인지 판별.

### 상세 내용

- 학습 후 각 특징(단어)의 **계수**가 나온다. 양수면 스팸 방향, 음수면 정상 방향 → 판단 근거가 그대로 노출되어 설명 가능.

---

## 3. 분류 모델 평가 지표

### 핵심 개념

- accuracy만으로는 부족하다. 특히 클래스 불균형이 심한 보안 데이터에선 **혼동 행렬** 기반 지표를 본다.

### 상세 내용

| 지표               | 정의                                 | 언제 중요                                            |
| ------------------ | ------------------------------------ | ---------------------------------------------------- |
| 정밀도 (Precision) | 위협이라 예측한 것 중 실제 위협 비율 | **오탐(FP)**을 줄여야 할 때                          |
| 재현율 (Recall)    | 실제 위협 중 탐지에 성공한 비율      | **미탐(FN)**을 줄여야 할 때 (위협을 놓치면 안 될 때) |
| F1-Score           | 정밀도·재현율의 조화평균             | 데이터 불균형이 심할 때 종합 성능                    |

- **오탐(False Positive)** = 정상을 위협으로. **미탐(False Negative)** = 위협을 정상으로 놓침. 보안에서는 대체로 미탐이 더 치명적이다.

---

## 4. 특징 추출 (Feature Engineering)

### 핵심 개념

- URL·HTTP 요청 같은 비정형 데이터를 ML 입력으로 만들려면 의미 있는 특징을 사람이 뽑아야 한다. 피싱 URL은 정상과 구별되는 구조적 특징을 가진다.

### 상세 내용

- **구조적 특징**: URL 전체 길이, 도메인 길이, 점(.) 개수, 하이픈(-)·특수문자, IP 직접 사용 여부.
- **통계적 특징**: `login`·`bank`·`verify` 같은 키워드 포함 여부, 자바스크립트 내 의심 함수 사용 빈도.

---

## 5. 랜덤포레스트 (Random Forest)

### 핵심 개념

- 결정 트리 여러 개를 독립적으로 학습시킨 뒤 **투표(Voting)**로 예측을 결정하는 앙상블.

### 상세 내용

- **배깅(Bagging)**: 중복 허용 무작위 추출(Bootstrap)로 트리마다 다른 데이터 학습.
- **무작위 특징 선택**: 노드 분할 시 일부 특징 후보만 사용 → 트리 간 상관을 낮춰 과적합 완화.
- **특징 중요도(Feature Importance)**: 지니 불순도 감소량 기준으로, 어떤 특징이 판별에 결정적이었는지 확인 가능(`feature_importances_`).

## 6. 악성코드 정적 분석 (PE 구조와 엔트로피)

### 핵심 개념

- **정적 분석**: 파일을 **실행하지 않고** 바이너리 구조와 속성만 분석하는 기법. 윈도우 실행 파일 포맷인 PE 구조에서 학습용 정적 특징을 추출한다.
- **PE (Portable Executable)**: 윈도우의 실행 파일·DLL·object 코드 표준 포맷. 32비트는 PE32, 64비트는 PE32+.

### 상세 내용

- **PE 구조 요소**: 헤더 영역(DOS Header, NT Header), 섹션 정보(`.text` 실행 코드 / `.data` 전역 변수 / `.rsrc` 리소스), 임포트 함수 목록(IAT, Import Address Table).
- **바이너리 엔트로피**: 파일 내 데이터의 무작위성·무질서도 지표. 암호화되거나 패킹(Packing)된 악성코드는 일반 코드 섹션보다 엔트로피가 높게 나타난다.

**악성코드가 남기는 정적 흔적 (실습 데이터 기준)**

| 유형                | 특징                                                         |
| ------------------- | ------------------------------------------------------------ |
| packed (패킹)       | 압축·암호화로 은닉 → 엔트로피 매우 높음(7.2+), 섹션·임포트 극히 적음 |
| obfuscated (난독화) | 코드 변형으로 분석 방해 → 엔트로피 중간(6.8~7.8), 섹션 많음, 서명 없음 |
| dropper             | 실제 페이로드를 나중에 내려받아 실행 → 파일 크기 매우 작고 URL 많음 |

- 공통 경향: 임포트가 적고(탐지 회피 위해 최소 API만 사용), 디지털 서명이 없다(코드 서명 인증서 취득이 어려움).

## 7. 앙상블 모델과 AUC-ROC

### 핵심 개념

- **GBM (Gradient Boosting Machine)**: 이전 모델의 예측 오차를 보완하도록 결정트리를 **순차적으로** 추가하는 부스팅 앙상블. 앞 트리의 실수를 다음 트리가 보정하며 성능을 점진적으로 올린다.
- 랜덤포레스트(배깅, 병렬·독립 학습 후 투표)와 대비되는 방식.

### 상세 내용

- **AUC-ROC**: 임계값(Threshold) 변화에 따른 **위양성률(FPR) 대비 진양성률(TPR)** 곡선. 곡선 아래 면적(AUC)이 1에 가까울수록 분류 성능이 우수하다.
- 즉 특정 임계값에서의 성적이 아니라, 임계값을 어떻게 잡든 두 클래스를 얼마나 잘 분리하는지를 본다.
