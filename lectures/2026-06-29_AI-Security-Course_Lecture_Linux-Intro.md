- 유닉스의 "Do one thing and do it well" 철학이 Docker의 "하나의 컨테이너는 하나의 프로세스"로 이어진다는 연결이 인상적이었다.

## 1. 운영체제와 커널 구조

### 핵심 개념
- 운영체제: 하드웨어와 소프트웨어 사이에서 자원 관리(메모리, CPU 등)를 담당하는 계층
- 소프트웨어 계층 구조: `HW(CPU/RAM)` → `커널(Kernel)` → `셸(Shell)` → `응용 프로그램(사용자)`

### CPU Protection Rings

- 개인적으로 찾아 본 내용

커널과 응용 프로그램의 권한 분리를 하드웨어 레벨에서 강제하는 구조.

| Ring | 역할 | 실제 사용 여부 |
|---|---|---|
| Ring 0 | 커널 — 최고 권한, 하드웨어 직접 접근 | ✅ 사용 |
| Ring 1 | 이론상 OS 서비스용 | ❌ 거의 미사용 |
| Ring 2 | 이론상 드라이버용 | ❌ 거의 미사용 |
| Ring 3 | 일반 애플리케이션 (Shell 포함) — 최저 권한 | ✅ 사용 |

> Shell은 Ring 3(응용 프로그램 계층)에서 동작한다. 커널 레벨 접근이 필요한 작업은 반드시 시스템 콜을 통해 요청해야 한다.

## 2. 유닉스/리눅스 역사와 철학

### 역사적 3대 전환점

| 연도 | 사건 | 의의 |
|---|---|---|
| 1973 | UNIX를 C 언어로 재작성 | 하드웨어 종속성 제거 → 이식성 확보 |
| 1983 | GNU 프로젝트 + GPL 탄생 | "소프트웨어는 자유롭게 공유되어야 한다" |
| 1991 | 리누스 토르발스, 리눅스 커널 공개 | GNU 도구 + Linux 커널 = GNU/Linux 완성 |

### UNIX 핵심 철학

> **"Do one thing and do it well"** — 하나의 도구는 하나의 일만 완벽하게

- 각 명령어(`ls`, `grep`, `awk`)는 단일 작업만 처리
- 파이프라인(`|`)으로 조합해 복잡한 작업 수행

```bash
# 로그에서 ERROR만 필터링해 상위 5개 추출
cat system.log | grep "ERROR" | tail -n 5
```

- **현대적 계승**: Docker의 "하나의 컨테이너는 하나의 프로세스" 원칙, MSA(마이크로서비스 아키텍처)의 설계 사상이 여기서 비롯됨

## 3. 오픈소스 라이선스 리스크

> 오픈소스는 "공짜 소프트웨어"가 아니다. 라이선스 위반 시 기업 소스코드 전체 공개라는 법적 리스크가 따른다.

### 라이선스 3대 분류

| 분류 | 대표 종류 | 핵심 의무 | 기업 실무 |
|---|---|---|---|
| 🟥 강한 카피레프트 | GPL, AGPL | 수정·결합 배포 시 **전체 소스코드 공개** | 상용 제품에 위험 |
| 🟨 약한 카피레프트 | LGPL, MPL | 링크·분리 사용 시 핵심 비즈니스 로직 비공개 가능 | 조건부 허용 |
| 🟩 퍼미시브 | MIT, Apache-2.0, BSD | 소스코드 공개 의무 없음, 저작권 표시만 | 기업 선호 |

### AGPL 주의사항 (최신 트렌드)
- 기존 GPL: 소프트웨어를 **배포**할 때만 소스 공개 의무
- AGPL: **SaaS로 서비스만 제공**해도 소스코드 전체 공개 의무 발생
- 대표 사례: 최신 MongoDB, Grafana 일부 플러그인

### AI 보안 관점
HuggingFace 등에 공개된 LLM 모델 가중치에도 라이선스가 혼재한다. AGPL이 붙은 모델을 서비스에 활용할 경우 소스코드 공개 의무가 생긴다. 모델 선택 단계에서 라이선스 확인은 필수 체크리스트.

## 4. 리눅스 배포판 지형도

### 양대 계열

- **데비안(Debian) / 우분투(Ubuntu) 계열**: 대중성 압도적, 커뮤니티 방대, AI 프레임워크 기본 타겟 OS. 서버 운영 시 LTS 버전 필수.
- **레드햇(Red Hat) 계열**: 금융·대기업·공공기관 엔터프라이즈 환경의 표준. 안정성과 호환성 최우선.

### CentOS 단종과 대안 (2026 기준)

CentOS는 RHEL 소스코드 기반의 무료 기업용 OS였으나, 레드햇이 개발 정책을 변경하며 공식 지원 종료(EOL).

| 대안 | 특징 | 용도 |
|---|---|---|
| **Rocky Linux** | RHEL과 바이너리 완전 동일 타겟팅 | 프로덕션 서버 |
| **AlmaLinux** | 빠른 보안 패치, 비영리 재단 운영 | 프로덕션 서버 |
| **CentOS Stream** | 향후 RHEL 기능 사전 테스트용 업스트림 | 개발·테스트 전용 (프로덕션 기피) |

### 상황별 선택 가이드

| 시나리오 | 배포판 | 패키지 관리자 |
|---|---|---|
| 개인 개발 / ML 학습 | Ubuntu LTS | `apt` |
| 기업용 백엔드 서버 | Rocky Linux / AlmaLinux | `dnf` / `yum` |
| 최신 커널 기능 테스트 | Fedora | `dnf` |
| 유닉스 내부 구조 학습 | Slackware / Debian | `pkg` / `dpkg` |

## 5. WSL (Windows Subsystem for Linux)

- Windows에서 리눅스 커널을 네이티브로 실행할 수 있게 해주는 호환성 계층
- 실습 환경: WSL2 + Ubuntu 22.04

### 기본 설정

```bash
sudo apt update && sudo apt upgrade -y
# sudo = superuser do: 일반 계정에서 관리자 권한으로 명령 실행
# sudo 없이 apt update → Permission denied (Ring 3 권한 제한)
```

### X11 / Wayland
WSL2는 WSLg를 통해 리눅스 GUI 앱 실행을 지원한다.

- **X11**: 1984년부터 사용된 리눅스 GUI 프로토콜. 클라이언트-서버 구조, 레거시 다수, 보안 취약점 존재.
- **Wayland**: X11 대체 현대 프로토콜. 컴포지터가 직접 렌더링, 구조 단순화 및 보안 강화. Ubuntu 22.04부터 기본값.
- WSLg는 두 프로토콜을 모두 지원하므로 X11 앱과 Wayland 앱 모두 실행 가능.
