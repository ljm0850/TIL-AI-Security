## 진행 과정

### Part 1. 환경 세팅

SSAFY SW 과정에서 Python, vscode, 라이브러리 설치 등을 이미 다뤄봤기 때문에 환경 세팅은 빠르게 진행했다. 그 시간에 환경 설정에 어려움을 겪는 동료를 도왔다.

**동료 트러블슈팅 — 시스템 환경 설정 문제**

- 동료의 시스템 환경 설정 문제를 함께 확인하고 해결했다.

**동료 트러블슈팅 — .env 로딩 순서 오류**

- OpenAI API 호출 시 오류 발생. 원인은 `.env` 파일을 읽어오는 `load_dotenv()` 코드가 API 호출 코드 **이후**에 작성되어 있었던 것.
- Python은 기본적으로 맨 위부터 코드를 한 줄씩 순차적으로 처리한다는 원리를 설명했다. `load_dotenv()`가 실행되기 전에 API 키를 참조하려 했으니 키를 읽지 못한 것.
- 해결: `load_dotenv()`를 API 호출 코드보다 앞으로 이동.

### Part 2. OpenAI API 첫 호출

환경 세팅 완료 후 직접 API 호출 코드를 작성했다.

```python
from openai import OpenAI
from dotenv import load_dotenv
import os

load_dotenv()  # .env 파일에서 환경 변수 로드 — API 호출보다 반드시 앞에 위치
# api_key = os.getenv("OPENAI_API_KEY")
# print(api_key)

client = OpenAI()
response = client.chat.completions.create(
    model="gpt-4o-mini",
    # temperature=0.7,   # 강의에서 배운 파라미터 — 추후 실험 예정
    # max_tokens=100,
    # top_p=1,
    messages=[
        {"role": "system", "content": "당신은 시니어급 개발자입니다"},  # Role Prompting 적용
        {"role": "user", "content": "python의 iterable과 iterator의 차이점에 대해 설명해줘"},
    ]
)

print(response.choices[0].message.content)
```

**코드에서 의식적으로 적용한 것들**
- `load_dotenv()`를 API 호출 앞에 배치 — 동료 트러블슈팅에서 직접 확인한 Python 순차 실행 원리 반영
- `system` role에 "시니어급 개발자" 페르소나 부여 — 강의에서 배운 Role Prompting 직접 적용
- `temperature`, `max_tokens`, `top_p` 주석 처리 — 파라미터 위치를 확인해두고 추후 실험 예정
- 질문 내용은 `iterable vs iterator` — API 호출 테스트 겸 이미 아는 개념으로 응답 품질 확인

## 느낀 것 / 배운 것

- 환경 세팅은 이미 아는 내용이었지만, 동료의 `.env` 로딩 순서 오류를 설명하면서 Python 순차 실행이라는 기본 원리를 다시 한번 명확하게 정리하게 됐다. 아는 것과 설명할 수 있는 것은 다르다는 걸 다시 확인했다.
- streamlit은 React처럼 별도 프론트엔드 없이 Python만으로 웹 UI를 빠르게 띄울 수 있다는 점이 인상적이었다. 백엔드 중심으로 개발해온 입장이라면 프로토타이핑 용도로 유용할 것 같다.
