## 실습 개요

- **방법**: Part 1 개인 실습(메모 앱) → Part 2 팀 실습(키오스크 프로토타입)

## 진행 과정

### Part 1. Figma 입문 — 메모 앱 만들기 (개인 실습)

강의에서 배운 핵심 기능을 직접 손에 익히기 위한 따라하기 실습.

| 단계 | 작업 내용 |
|---|---|
| Step 1 | Frame 생성 (iPhone 16 규격), 이름 Memo_List로 변경 |
| Step 2 | 상단 바에 'My Memos' 텍스트 배치, 레이어 구조 확인 |
| Step 3 | Variables 패널에서 색상 변수 등록 (BgDefault, Text-Main 등), 메모 카드 제작 후 Component 생성 |
| Step 4 | Auto Layout(Shift+A) 적용 — 카드 내 Padding 설정, 카드 복사(Ctrl+D) 후 리스트 그룹화 |
| Step 5 | Variables Mode로 다크 모드 변수 추가, 모드 전환 테스트 |
| Step 6 | Memo_Detail 프레임 추가 후 Prototype 탭에서 카드 → 상세 화면 인터랙션 연결 및 동작 확인 |

---

### Part 2. 키오스크 프로토타입 제작 (팀 실습)

어제 완성한 PRD를 기반으로 음식점 키오스크 화면을 Figma로 제작.

**설계 범위**: 키오스크 앞에 서있을 때 뜨는 첫 화면 → 음성 주문 → 결제 화면

**접근 방식 비교**

팀원 2명이 각각 한 화면씩 그렸는데, 도구 활용 방식과 결과물의 방향이 달랐음.

| 구분 | 나 | 팀원 |
|---|---|---|
| 도구 활용 | Google Stitch로 일반 키오스크 화면 흐름 파악 → 참고용으로만 사용 | Google Stitch로 디자인 완성도 높은 화면 생성 |
| Figma 작업 | Frame·도형·텍스트로 기능 중심 Lo-Fi 화면 직접 작성 | Stitch 결과물을 Figma에 붙여넣기 (자동 컴포넌트화됨) |
| 완성도 | 낮음 — 구조와 흐름 중심 | 높음 — 실제 서비스처럼 보이는 수준 |
| 핵심 기능 가시성 | 음성 인식 흐름이 명확하게 드러남 | 디자인에 가려져 핵심 기능이 잘 보이지 않음 |

**강사님 피드백 (팀원 방식에 대해)**
- 고객은 완성된 프로토타입을 보면 그보다 더 좋은 완성품을 기대한다
- 완성도 높은 디자인이 오히려 '자연어 음성 인식'이라는 아이디어의 핵심을 가렸다
- 프로토타입 단계에서는 핵심 기능과 흐름이 먼저 보여야 한다

## 잘 된 것 / 안 된 것

| 잘 된 것 | 안 된 것 |
|---|---|
| Auto Layout + Component 조합의 수정 편의성을 직접 체감 | Part 2 시작 전 팀 내에서 프로토타입 목적(팀 내 검토용 vs 고객 제시용)을 합의하지 않음 |
| 기능 흐름 중심으로 화면을 그려 핵심 아이디어가 명확하게 드러남 | Figma 숙련도가 낮아 의도한 레이아웃 구현에 시간이 걸림 |

---

## 느낀 것 / 배운 것

- 강사님 피드백 중 "완성된 디자인이 아이디어의 핵심을 가린다"는 부분은 동의했다. Hi-Fi로 갔을 때 보는 사람의 시선이 기능이 아닌 디자인으로 쏠리는 건 분명한 리스크다.
- 내가 한 작업은 팀 내 구조 검토용 Lo-Fi였지, 고객에게 제시하는 수준이 아니었다. 같은 Figma 파일인데 나는 Lo-Fi, 팀원은 Hi-Fi로 접근했다는 건 **프로토타입의 목적을 서로 다르게 이해하고 있었다**는 뜻이다.
- 결국 작업 시작 전에 "이게 팀 내 검토용인가, 고객 발표용인가"를 먼저 합의해야 한다는 걸 배웠다. Fidelity 수준을 맞추는 것도 팀 협업의 일부다.
