## 느낀 것 / 배운 것

### 📅 2026-06-25

- **하나의 앱이 "이미지 입력 → 텍스트 → 음성 출력"으로 연결하는 것이 인상적이었다.** ag_08_1에서 이미지를 *읽고*(vision), ag_08_3에서 그걸 영어 퀴즈로 *바꾸고*, ag_08_4에서 그 텍스트를 *말로*(TTS) 만든다. LLM 호출이 하나의 텍스트 작업이 아니라, 입력·출력 모달리티를 갈아끼우는 블록이 됐다.
- **로컬 이미지는 base64로 인코딩해 "문자열로" 모델에 넣는다는 게 핵심 트릭이었다.** 과거에 팀프로젝트에서 이미지를 firebase에 저장 하면서 base64로 인코딩 했던 적이 있다. 그 당시 이것이 무엇을 하는 건지 잘 이해하지 못하고 작성했던 것이 생각났다. URL 이미지는 그냥 주소를 주면 되지만, 로컬 파일은 URL이 없으니 `base64.b64encode(...)`로 인코딩해 `data:image/jpeg;base64, {...}` 형태의 data URI로 넘긴다.
- **AI 보안/신뢰성 — 비전 모델이 차트의 "정확한 숫자"를 환각한다.** ag_08_1에서 OECD R&D 차트를 읽혀보니 한국 GDP 대비 비율을 4.93%→2.91%처럼 *구체적 수치로* 답했는데, 비전 모델은 이런 정밀한 값을 그럴듯하게 지어내기 쉽다. 이미지에서 뽑은 숫자를 검증 없이 신뢰하면 위험하다. "해상도 높을수록 결과가 좋다"는 관찰도 같은 맥락 — 입력 품질이 떨어지면 환각 위험이 커진다. **이미지 기반 자동 판독은 "참고"지 "근거"가 아니다.** 이는 이후 프로젝트에서 이미지 분석이 들어갈 경우 매우 신중하게 생각해야 할 문제라고 생각된다.
- **이미지도 새로운 인젝션 표면이다.** 사용자가 올린 이미지에 텍스트(지시문)가 박혀 있거나 미세 조작이 가해지면, 비전 모델이 그걸 지시로 받아들이거나 오인식할 수 있다. "외부 콘텐츠를 프롬프트에 넣는 위험"이 모달리티만 바뀌어 이미지로 확장된 셈. CNN의 "픽셀 민감성 → 적대적 예제" 주제가 멀티모달 LLM에서도 살아있다.
- **(효율 메모) 파일 저장을 반복문 안에 둔 건 비효율이지만, 의도된 단순화로 봤다.** ag_08_3에서 매 이미지마다 전체 txt/json을 다시 통째로 파일에 쓴다(루프마다 재기록). 비효율이지만, 이번 학습의 핵심은 big-O가 아니라 *API를 엮어 서비스 흐름을 만드는 것*이라 이렇게 둔 것으로 이해했다.

## 실습 개요
- **목표**: 멀티모달 LLM으로 (1) 이미지 설명·비교, (2) 이미지 기반 퀴즈 생성(한/영), (3) 영어 퀴즈를 TTS로 음성화하는 응용 만들기.
- **도구**: OpenAI API (gpt-4o-mini 비전, tts-1-hd), base64, glob.

## 진행 과정

### Step 1. 이미지 설명 (ag_08_1)
```python
# URL 이미지: 주소 그대로 전달
messages = [{'role':'user','content':[
    {'type':'text','text':'이 이미지에 대해 설명해주세요'},
    {'type':'image_url','image_url':{'url':'https://...'}}]}]

# 로컬 이미지: base64로 인코딩 후 data URI로 전달
def encode_image(path):
    with open(path,'rb') as f: return base64.b64encode(f.read()).decode('utf-8')
# 'url': f'data:image/jpeg;base64, {base64_img}'
```
- 이미지 2장을 함께 넣어 "사업가 시선에서 두 카페 비교", "2021 vs 2022 R&D 차트 변화" 같은 비교도 가능.

### Step 2. 이미지 퀴즈 생성 — 한국어 (ag_08_2)
- 프롬프트에 출제 양식 + 예시(정답 (1)~(4) 중 하나)를 주고, `glob('data/ch06/*.jpg')`로 여러 이미지를 순회해 `image_quiz.md`로 저장.

### Step 3. 영어(토익 리스닝) 퀴즈 + 재시도 (ag_08_3)
```python
def image_quiz(image_path, n_trial=0, max_trial=3):
    if n_trial >= max_trial: raise Exception('문제 생성 실패')
    ...
    content = response.choices[0].message.content
    if 'Listening:' in content:        # 원하는 포맷이 나왔는지 검증
        return content, True
    else:
        return image_quiz(image_path, n_trial+1)   # 재귀로 재시도
```
- "Listening:"이 포함될 때까지 **재귀 재시도** — LLM 출력이 형식을 안 지킬 때의 방어 패턴. 영어 문제만 추출해 json으로도 저장.
- ⚠️ **버그/오타 2개**: (a) data URI에 `data:image/jepg`로 오타(jpeg). (b) `print('실패\n' + ex)`는 문자열+예외 객체 연결이라 그 자체로 `TypeError` — `str(ex)`로 감싸야 함.

### Step 4. TTS로 듣기 문제 생성 (ag_08_4)
```python
voices = ['alloy','ash','coral','echo','fable','onyx','nova','sage','shimmer']
for q in eng_dict:
    quiz = q['eng'].replace('- (1)','- One.\t')...   # 보기 번호를 영어 낱말로
    voice = voices[q['no'] % len(voices)]            # 문제마다 다른 목소리
    response = client.audio.speech.create(model='tts-1-hd', voice=voice, input=f"#{q['no']}. {quiz}")
    response.write_to_file(f"output/ch06/{q['no']}.mp3")
```
- ag_08_3이 만든 영어 퀴즈 json → 문제별 mp3. 모달리티가 텍스트 → 음성으로 한 번 더 전환.
